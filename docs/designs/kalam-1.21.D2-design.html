#Rule
1Manifest first, never scrape. The app fetches one small update.json from the release (versionCode, versionName, apk URL, sha256, size, releaseDate, notes). No GitHub API calls, no rate limits, no tokens.
2Background check: WorkManager periodic job, every 24 h, network-required, battery-friendly. Also Check now in Settings. First check runs ~1 min after install.
3Decision: update offered only if manifest versionCode > installed. Same-or-lower is silently ignored (protects against a bad manifest).
4Download: DownloadManager to app-private cache; SHA-256 verified against the manifest before install; mismatch → file deleted, “Update failed verification” shown, nothing installed.
5Install: hands the verified APK to the Android package installer (FileProvider + REQUEST_INSTALL_PACKAGES). Android shows its own confirm sheet; first time it asks you to allow “install unknown apps” for Kalam — one-time.
6Signing: Android refuses an update signed with a different key. All releases so far are debug-signed with this container's throwaway key — that key is lost on every container reset. So K83 introduces a stable release keystore (generated once, kept by you, supplied to me at build). The first GitHub release will need a one-time uninstall/reinstall because the signature changes; every release after that updates in place. Blocker 3.
7Never nags: one notification per new version; “Later” silences it until the next version. No auto-install without your tap.
8Fail-safe: any error (offline, 404, bad JSON, bad hash) → logged, quietly retried next cycle; the app never blocks or degrades because updates are unreachable.
9Companions: manifest parser + version-compare vectors, SHA-256 verify vectors (good/bad/truncated), “lower version ignored” vector, one log line per check; a real manifest for the shipping version is baked as a test fixture.
